# A fresh number must serve a decision, come through a documented API and show its age

Stillstats shows a number when three things hold: it can inform a decision the creator can still make, it comes through a documented YouTube API under the creator's OAuth grant, and it shows its age. A number that only rewards checking stays out, however fresh. That is ADR 0011's reasoning applied to time: a figure that refreshes so the creator comes back to watch it move is an attention trick, the same as a streak. The first hours after an upload, while the title and thumbnail can still change, are a real decision point, so a fresh figure there can pass. This sits beside ADR 0011 and binds the web app (#2), the Studio extension (#4) and the site, as ADR 0011 does.

ADR 0003 and ADR 0008 stand unchanged. No documented API gives realtime engaged views: the Analytics API runs 48 to 72 hours behind, and `videos.batchGetStats` returns only the current `viewCount`, `likeCount` and `commentCount`. So the fourth question in the compliance audit application's scope (#6) asks Google in writing whether the Studio extension may read a creator's own realtime engaged views from Studio, for that creator's own channel only and shown only to them. A written yes gets its own ADR, which supersedes ADR 0003 and ADR 0008 for that one endpoint and nothing else. No answer, or a no, changes nothing.

The first number weighed under this rule failed it. #256 built a line above Studio's Realtime card with the channel's engaged views for its last two processed days and the ratio of views to engaged views on those days. It was dropped on 2026-11-08, at the first look in a real browser and before its pull request. The line repeated the web app's engaged views card, and beside Studio's live views it informed no decision the creator can still make. A processed figure that only repeats a number the creator already sees elsewhere fails the first test, wherever it is placed. The line's code stays on the branch `creator-analytics-256-realtime-card-line` and is not merged.

Five routes to a fresh engaged views figure were weighed and rejected.

Studio's private endpoints, called with the creator's browser session, as vidIQ and RealView do. Developer Policies III.D.7 says "You must not use undocumented APIs without express permission", III.I.14 says API clients must not "use any technology other than YouTube API Services to access or retrieve API Data", and ADR 0003 already rules out private endpoints and the creator's session.

The same read done only in the browser, with the figure never sent to the product API. The Developer Policies define an API client as "a website or software application (including a mobile application) developed by you that accesses or uses the YouTube API Services", so they bind the client as a whole and not only its server. The extension is part of that client, and the read carries the same risk in a different place. ADR 0008 also forbids the extension to use the browser session against YouTube.

Reading the figures Studio draws on the page. That is scraping under III.E.6: "You and your API Clients must not, and must not encourage, enable, or require others to, directly or indirectly, scrape YouTube Applications or Google Applications". ADR 0008 lets the extension read the channel id, video ids and the selected period from the page, and never a number.

An estimate of realtime engaged views, such as Studio's live views times the ratio of processed engaged views to views. III.E.4.h says API clients "must not (i) replace API Data with similar, independently calculated data", and an estimated engaged views figure is exactly that. The derived-metrics policy keeps the general rule, that developers are "generally prohibited from creating metrics that replace or modify the data returned by the YouTube API Services", and permits specific additional metrics only to a developer who accepts its amendment to the Developer Policies. The estimate it allows is a financial one, "Financial Performance Projections", which must be "clearly presented as third-party estimates". Engaged views are not financial performance, and Stillstats accepts no amendment before the compliance audit (ADR 0004). The ratio of views to engaged views itself stays: it is simple arithmetic on the channel's own two numbers under ADR 0013, shown beside Studio's views, and never multiplied into an estimate.

A second app without OAuth, reading Studio for the same creators outside the verified client. YouTube's Terms of Service forbid anyone to "access the Service using any automated means (such as robots, botnets or scrapers)" except for public search engines or "with YouTube's prior written permission". III.E.6 forbids an API client to "encourage, enable, or require others to, directly or indirectly, scrape", so a sister app for the same creators puts the verified client at risk. And it would be RealView under another name.

The sources, read on 2026-11-06:

- The Developer Policies, https://developers.google.com/youtube/terms/developer-policies, marked "Last updated 2026-11-06 UTC". III.D.7, "Undocumented Services": "You must not use undocumented APIs without express permission. You must access data from YouTube API services only according to the means stipulated in the authorized documentation of that YouTube API service." III.E.4.h: "Your API Clients must not (i) replace API Data with similar, independently calculated data, or (ii) access or use API Data to create new or derived data or metrics." III.E.6, "Scraping": "You and your API Clients must not, and must not encourage, enable, or require others to, directly or indirectly, scrape YouTube Applications or Google Applications, or obtain scraped YouTube data or content." III.I, "Additional Prohibitions", lists what API clients must not do, and its item 14 is "use any technology other than YouTube API Services to access or retrieve API Data, including to access any portion of any YouTube audiovisual content". Section IV defines "API Client" as "a website or software application (including a mobile application) developed by you that accesses or uses the YouTube API Services".
- The YouTube Analytics and Reporting APIs data model, https://developers.google.com/youtube/analytics/data_model, marked "Last updated 2026-11-05 UTC", under "Data freshness and latency": "analytics data is not real-time. Data processing typically introduces a latency of 48 to 72 hours."
- `videos.batchGetStats`, https://developers.google.com/youtube/v3/docs/videos/batchGetStats, marked "Last updated 2026-11-03 UTC": "Retrieves a list of video statistics that match the API request parameters." Its response's `statistics` carries `viewCount`, `likeCount` and `commentCount`, and nothing else.
- The derived-metrics policy, https://developers.google.com/youtube/terms/derived-metrics-policy, marked "Last updated 2026-09-14 UTC": "As a developer, you are generally prohibited from creating metrics that replace or modify the data returned by the YouTube API Services. However, subject to your acceptance of the amendment to the Developer Policies, to support advanced analytics and creator tools, YouTube permits the calculation of specific additional metrics". Under "Financial Performance Projections": "You may infer or project the financial performance of a YouTube channel (e.g. estimated revenue), provided these figures are clearly presented as third-party estimates and not as YouTube approved or published data."
- The quota and compliance audits guide, https://developers.google.com/youtube/v3/guides/quota_and_compliance_audits, marked "Last updated 2026-11-03 UTC": "If you would like to request additional quota beyond the default allocation, you must first complete an audit to show that your project is in compliance with the YouTube API Services Terms of Service." It names forms for an audit and quota extension, an appeal, a periodic audit and a change of control, and none for permission to use an undocumented API, which is why the request rides in #6's audit application.
- YouTube's Terms of Service, https://www.youtube.com/t/terms, "Effective as of December 15, 2023". Among the things a user is not allowed to do: "access the Service using any automated means (such as robots, botnets or scrapers) except (a) in the case of public search engines, in accordance with YouTube's robots.txt file; or (b) with YouTube's prior written permission".

This is recorded so that a later realtime feature that takes one of the rejected routes, a private endpoint, a browser-only read, a scraped figure, an estimate or a sister app, is visibly a breach of a decision rather than a faster way to ship.
